# Session 2026-10-26 (evening): the phone gate, the split playlist, and a release

Everything here was driven through the running app or its bridge, and the effect
was checked - not just `{"ok":true}`. Numbers come from `/state`, `/playlists`,
`/library`, the on-disk room files, and the request timings printed by curl.

---

## 1. "that route is local only" - the bug behind both phone complaints

Two symptoms, one cause:

- adding a song from the phone (stream **or** download) failed, and
- the home-screen icon stayed an "A" after deleting and re-adding it.

The LAN gate was an **allow-list** (`LAN_ROUTES`) of what a phone could reach.
`/playlist/add_web`, `/playlist/covers`, `/playlist/cover`,
`/apple-touch-icon.png` and `/manifest.webmanifest` were all written after that
list and were answered with the refusal above. iOS, unable to fetch
`apple-touch-icon.png`, falls back to drawing the page's first letter - hence the
"A" that survived re-adding the bookmark (it was never a caching problem).

**Fix:** invert the gate. Everything answers the LAN except `LOCAL_ONLY` in
`src/server.rs`: the gateway switch, the diag channel, the Windows shell
harness, credentials/OAuth/Spotify, appearance writes, `/config`, `/rescan`,
queue surgery, and any route that takes a filesystem path from the caller.

Also fixed while there: `respond_bytes` wrote its header block with bare LF
instead of CRLF. Tolerable for curl, not something to hand Apple's fetchers.

**Verified** from the machine's own LAN address (`192.168.1.240:3690`, so the
peer is non-loopback exactly as a phone is):

| request | result |
| --- | --- |
| `/apple-touch-icon.png` | `200 image/png 28224` (also `-precomposed`) |
| `/manifest.webmanifest` | `200 application/manifest+json 307` |
| `/playlist/add_web?...&mode=stream` | `{"ok":true,"msg":"added as a stream"}`, row on disk with `web` + cover, **5.8 s** |
| `/playlist/add_web?...&mode=file` | row at once, upgraded to a local `.mp3` when the download landed |
| same URL twice | `{"duplicate":true}` |
| `/room/audio?id=&row=0` (stream row) | `200 audio/mp4 2.5 MB` relayed |
| `/room/audio?id=&row=1` (downloaded row) | `200 audio/mpeg 11.4 MB` from disk |
| `/phone` `/accounts` `/config` `/eq` `/shell/state` `/rescan` | still `that route is local only` |

## 2. "there's only 63 but the playlist has 100+ songs"

The shelf was listing a legacy room (`library/my_playlist.json`, 74 rows) and
`library/playlists/luxiouris.json` (25 rows) **under the same name**, so the room
the user opened was never the whole list.

Merged by title+artist (9 duplicates folded) into the active room: **74 + 25 ->
90 rows**, both files backed up to `library/backups/` first, and the legacy file
moved out of the shelf. `playlist_rows` no longer advertises a file outside the
playlists folder.

Rooms can now also **rename** and **retire** themselves from a hover menu on
their card:

- `GET /playlist/rename?id=&name=` rewrites only the name, updates the name in
  memory when it is the open room.
- `GET /playlist/retire?id=` moves the file to `library/backups/` and refuses
  while it is the open room (`that is the open room - open another one first`).
  Nothing is ever deleted, so a wrong press is a move back.

**Trap found while testing:** creating a room switches the active room, so
"retire the open one" protects the *new* room, not the one you were playing.
The refusal fired correctly; the test had switched first. Worth knowing before
scripting anything that retires rooms by id.

## 3. A row with no length and no name

The audit caught `duration matches file  147356 vs 0` on a real song: the room
row was `"title": "untitled", "duration_ms": 0`. A row like that shows `0:00`,
cannot be timed against lyrics, and sends lrclib a useless query.

`load_all` now heals those from the file itself (symphonia probe, local only):
duration when it is 0, and name/artist when the title is empty or "untitled".
**2 rows healed** on the first launch, the room file rewritten once, and the
audit's duration check became `126511 vs 126511`.

## 4. Lyrics: the matcher was too literal

A download named `Peachy__ mxmtoon - Falling For U (feat_ mxmtoon)` with artist
`Unknown Artist` returned nothing - while lrclib has the song 16 times as
"Falling For U" by Mxmtoon.

Two holes:

1. `lyric_clean` only cut at `" feat. "` / `" ft. "`. A download writes `feat_`
   (underscores), and bracketed credits were never removed. Now: underscores
   become spaces, a bracketed group that *credits* somebody (`feat`, `ft`,
   `prod`, `remix`, `live`, ...) is dropped as a group, and the bare cut list
   includes `feat` and `prod` without punctuation.
2. The "artist - title" recovery only ran when the artist was in a short
   generic list that contained `unknown` but **not** `unknown artist`, and the
   recovered-title variant was only pushed inside that branch. Now
   `unknown artist`/`various`/`the web` are generic too, the recovered variants
   are pushed unconditionally at the end of the ladder, and the ladder tries 6
   variants instead of 4.

**Verified:** the same query returns `synced True chars 960`, starting
`[00:20.27] I was hangin' with you and then I realized`.

Cache consequence: a "miss" recorded by the old matcher used to suppress the
song for 7 days. Misses are now versioned (`LYRICS_MATCHER`); an older miss is
deleted and retried once, while real lyrics stay cached. Confirmed by asking for
the track by id with **no** `refresh=1`: 936 chars, synced.

## 5. It had to be buildable by someone else

- QML had 24 absolute paths (`file:///C:/Aether/custom_spotify/...`). All are
  now `Qt.resolvedUrl("../assets/...")`, so the UI resolves its own neighbours
  from wherever the checkout lives. Verified by restarting and screenshotting:
  nav icons, app icon, cover art, sound effects all still load.
- `MUSIC_DIRS` was hardcoded to one person's profile. `music_dirs()` now reads
  `%USERPROFILE%` and `AETHER_MUSIC` (semicolon separated), and the download
  target (`out_dir()`) does the same instead of pinning `C:/Users/Owner/Music`.
  Verified: 120 rows (30 local vault + 90 room) after the change.

## 6. Audit harness

Two ways the audit lied:

- It printed the room name (¥𝒆𝒏×𝑻𝒑𝑭★彡) to a cp1252 console and died with
  `UnicodeEncodeError` **halfway through**, leaving the active room switched to
  its temp room. `sys.stdout.reconfigure(encoding="utf-8")` at the top.
- The lyrics check failed whenever lrclib simply had no entry for the song, which
  measures the internet rather than the app. It now asks lrclib first and
  records a note when upstream has nothing, failing only when upstream *has*
  lyrics and the app returns none.

Final run: **FAILS=0**, `notes: 7 artless local files use the designed gradient fallback`.

## 7. Release

`github.com/Tpfjae-Aether/aethermix` - public, MIT, with:

- README rewritten as a front page: what it is, the feature set, six screenshots,
  the 33-second showcase, build steps, the phone route, keyboard map, docs.
- `docs/media/01..06-*.png` captured with **CopyFromScreen**, not `PrintWindow`:
  PrintWindow cannot see the Quick3D layer, which is why earlier screenshots of
  the Themes page came out black.
- `.gitignore` keeps `library/`, `cache/`, `extensions/`, accounts, OAuth tokens,
  `config.json`, `bin/*.exe`, `target/` and `.scratch/` out of the repo.
- `nul`: MSYS leaves a *real* file called `nul` when a Windows command redirects
  to `nul` from a POSIX shell. Windows cannot address it through its own APIs,
  and `git add` dies with `short read while indexing nul`. It is git-ignored.

No prebuilt zip: `AETHER_ROOT` is resolved at build time, so a binary built on
one machine reads that machine's folders. Runtime-resolving those 46 sites is
the work that would make a downloadable release honest.
